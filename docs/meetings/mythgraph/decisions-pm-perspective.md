## 🎯 OQ-1: Entity 라벨 전략

### 선택: 공통 Entity + 보조 라벨

**근거:**
- **사용자 검색 경험:** 신, 인간, 괴물을 하나의 검색 인터페이스에서 통일하게 제시
- **GraphQL 정규화:** 공통 `Entity` 인터페이스로 프론트엔드 컴포넌트 통일
- **데이터 확장:** 새로운 라벨 추가 시 기존 데이터 무영향

**영향 범위:**
- 검색 UI: 단순화 (필터만 추가)
- Seed 데이터: 라벨 분류 명확화 필요
- 향후 확장: 신화 속 부족, 아이템 등 추가 시 용이

**이월 리스크:** 낮음 (분리 노드로 변경 시 3-4일 소요, 회피 권장)

## 🎯 OQ-2: Myth/Event 노드 포함 여부

### 선택: 별도 노드 생성 (P0 필수)

**근거:**

**1. Sprint 2 의존성 (MG-05 "Myth 탐색")**
```
Sprint 2 목표: Entity 간 관계 탐색
└─ MG-05: 신화 중심으로 관련 인물/사건 발견
   └─ 필요: Myth 노드 + Event 노드
```

**2. 마이그레이션 불가능성**
- 관계 속성으로 구현 시: Event의 독립 검색 불가능
- 나중 추가 불가능: Entity-Entity 관계 재설계 필수 (1주 소요)
- **이번 결정이 앞의 결정이 아니면 진행 불가능**

**3. Seed 데이터 구조 영향**
- Myth 10-15개 추가 필요 (기준 문헌 선정)
- Event 15-25개 추가 필요 (시간순 정렬)
- **PM 작업 +1.5일 추가**

**영향 범위:**
- Step 2-3: Schema 설계 확대 (Entity만 → Entity + Myth + Event)
- Step 4-5: Seed 데이터 수집 +2일
- QA: 관계 무결성 테스트 추가

**이월 리스크:** 매우 높음 (5-7일 마이그레이션 불가피)

## 🎯 OQ-3: 벡터 임베딩 공급자

### 선택: 결정 유보 (Sprint 3 구현 시점에 선택)

**근거:**

**1. 필요 시점이 다름**
```
Sprint 1-2: Keyword 검색 (full-text index) 충분
Sprint 3: 의미 검색 (MG-06) 구현 시 도입
```

**2. 비용 절감**
```
지금 결정 시:
├─ OpenAI: $200-300/월 (불필요한 선투 비용)
├─ DeepSeek: $50-100/월 (3개월 $150-300 낭비)
└─ 로컬: $0 (인프라 추가 복잡도)

Sprint 3 도입 시:
└─ DeepSeek: 필요할 때만 시작
```

**3. 기술적 유연성**
- 공급자 변경 비용 낮음 (2-3시간)
- 나중 도입해도 마이그레이션 간단
- 성능 평가 후 선택 가능

**영향 범위:**
- Step 1-2: 인터페이스 설계만 (3.5시간)
- 비용: Sprint 1-2 $0 유지
- 유연성: Sprint 3에서 최적 공급자 선택 가능

**이월 리스크:** 낮음 (언제든 추가 가능)

## 🎯 OQ-4/OQ-5: Neo4j 계정 분리

### 선택: dev/prod 완전 분리 (P0 필수)

**근거:**

**1. 운영 안정성**
```
dev에서 Seed 재로드 중 → prod 영향 0
dev 개발자의 쿼리 오류 → prod 서비스 무영향
```

**2. 초기부터 분리하지 않으면 불가능**
- 나중 마이그레이션: 1주 소요 (모든 데이터 추출-변환-로드)
- 자격증명 분리 재작업 필수
- CI/CD 파이프라인 재구성 필수

**3. Aura 무료 평가판 지원**
- ✅ 2개 인스턴스 동시 생성 가능
- ✅ 무기한 무료 (신용카드 불필요)
- ⚠️ 30일 미활동 시 자동 삭제 (개발 활동이면 문제 없음)

**영향 범위:**
- Step 1: 환경 구성 (30분)
- Step 2-3: Driver 초기화 (1.5시간)
- CI/CD: Vercel 자격증명 분기 설정 필수

**이월 리스크:** 높음 (초기 결정 필수)
