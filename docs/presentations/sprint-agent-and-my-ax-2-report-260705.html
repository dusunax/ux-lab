제품 확장

탐색 앱에서 운영 가능한 Agent Hub로 확장

1
Create Agent
Platform, Usage Guide, Visibility, resultPreset, downloads까지 작성자가 등록한다.
2
Profile
작성 Agent, 써봤어요, 좋아요, Fork, 요청 활동을 실명 기반으로 확인한다.
3
Request Board
필요한 Agent를 요청하고 투표와 상태 badge로 수요를 모은다.
Sprint 2의 핵심은 Agent 소비 화면이 아니라 작성자와 사내 운영자 모두가 쓸 수 있는 순환 구조다. 등록, 요청, 활동 데이터가 repository action을 경유하도록 정리했다.
주요 결정

Sprint 2 결정 사항

D-2 / D-9Firebase production 연결 전 repository interface와 mock adapter를 먼저 완성한다.
D-4Google Workspace SSO는 mock shell과 current user provider까지만 구현한다.
D-5 / D-10Agent 등록 폼은 resultPreset과 다운로드 산출물까지 P0 필드로 포함한다.
D-6 / D-11Request Board는 전체 공개 요청만 허용하고 투표/상태 기반 운영 채널로 둔다.
D-7 / D-12Profile 기본 진입점은 `/me`, 공유 URL은 `/profile/[userId]`로 둔다.
D-13Fork 생성은 Sprint 2 P1로 유지하고 필수 Create 플로우에서 제외한다.

다운로드 UX

여러 Agent가 공유 가능한 산출물 형태

  • Cursor, Claude, Codex, Prompt 형식 다운로드 제공
  • 다운로드 가이드는 기본 닫힘 상태의 단일 아코디언
  • 각 파일의 넣는 곳과 사용법을 얇은 행 단위로 안내
  • Detail과 Run에서 같은 컴포넌트를 재사용
작성자가 만든 Agent 결과를 현재 UI대로 보여주기 위해 `resultPreset`과 `downloads`를 Agent 데이터 필드로 고정했다.

Auth / 상태 UX

로그인 필요 상태와 오류 문구 검토

로그인 필요 상태: 제한 기능과 SSO mock 진입점을 명확히 안내
  • 새 Agent, 요청 등록, 댓글, 좋아요, 써봤어요는 로그인 필요 상태를 일관되게 표시
  • API write route는 logged-out 상태에서 401과 사용자 문구를 반환
  • 빈 상태는 다음 행동을 제시하고, validation 실패는 빨간 오류 영역으로 분리
  • SSO shell은 실제 OAuth 전환 전 current user provider 계약을 고정
